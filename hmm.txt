# CYBERPUNK 3D PORTFOLIO — MASTER BUILD SCRIPT

ROLE OF THIS DOCUMENT
This document is an implementation specification for an AI coding agent.
Do not treat it as a visual moodboard only.
Every scene must be implemented as an actual interactive 3D experience.
The portfolio must be driven by the engineer profile and projects supplied in the resume.
Do not invent employment history, projects, metrics, clients, awards or technologies.
Use illustrative technical data only when a visual animation requires sample payloads.

# CORE CREATIVE DIRECTION
The theme is CYBERPUNK, NOT SPACE.
Do not create planets, galaxies, nebulae, star fields, astronauts or outer-space environments.
The visual language should feel like a futuristic city, underground systems lab, neon data center and advanced interface combined.
Use wet black surfaces, smoked glass, translucent polymer, brushed dark metal, holographic panels, cables, rails, terminals and architectural grids.
The environment should feel physical and urban rather than cosmic.
Use neon cyan, acid green, electric violet and controlled white as accent colors.
Never use rainbow gradients.
Never turn every object into glowing neon.
Most surfaces should remain dark and restrained.
Glow is reserved for active data, interaction states and important edges.

# TECHNICAL REQUIREMENT
Use Next.js App Router.
Use TypeScript.
Use React Three Fiber for WebGL.
Use Drei for helpers and loaders.
Use GSAP with ScrollTrigger for scene choreography.
Use Framer Motion for DOM typography and interface overlays.
Use GLSL shaders for particles, distortion, displacement and transition effects.
Use react-three/postprocessing for bloom, depth of field and other post effects.
Use Lenis for smooth scrolling if it integrates cleanly with ScrollTrigger.
Use instanced rendering for repeated particles and repeated geometry.
Use dynamic imports for heavy 3D scenes.
Do not enable OrbitControls in production.
The camera must be controlled by the experience.

# IMPORTANT SCROLL RULE
Do not build a normal page where the WebGL scene simply sits behind HTML sections.
Scrolling must drive the 3D narrative.
The page can still use native scroll position as the timeline driver, but the visual result must feel like a sequence of cinematic scenes.
Each scene owns a normalized progress range.
GSAP ScrollTrigger controls scene progress.
Camera, object transforms, particles, postprocessing and DOM typography must all respond to the same scene progress.
Use power3.inOut, power2.inOut, expo.out and custom cubic-bezier easing.
Avoid linear easing for visible object motion.

# CAMERA RULES
Use one main PerspectiveCamera for the cinematic experience.
Use secondary cameras only when technically necessary.
Camera movement must be smooth and damped.
Do not snap the camera between scenes.
Use small camera shake only during major scene transitions.
Never use camera shake continuously.
Camera shake should be deterministic and subtle.

# CURSOR RULES
Create a custom DOM cursor.
The default browser cursor should be hidden on desktop.
The cursor has an inner dot and an outer ring.
The outer ring expands over interactive objects.
The ring changes shape slightly when hovering a 3D interactive object.
The cursor should not become so large that it blocks content.
Use raycasting for 3D hover detection.
Use throttled pointer calculations where necessary.

# PARTICLE RULES
Particles are not decorative stars.
They represent data, electricity, dust, signal fragments and system activity.
Use shader-based particles.
Use instanced or GPU-friendly rendering.
Particles should have depth fade.
Particles should have soft glow.
Particles should respond to cursor proximity.
Particles should react to scene progress.
At high scene intensity, particles should accelerate and spread.
At calm moments, particles should regroup into structures.

# MATERIAL RULES
Primary surfaces: dark smoked glass.
Secondary surfaces: black anodized metal.
Interactive edges: controlled neon emissive material.
Glass objects should use MeshPhysicalMaterial where appropriate.
Use transmission carefully; do not make every surface fully transparent.
Use roughness variation to create realistic glass.
Use subtle iridescence on hero objects only.
Chromatic aberration should be restrained.

# LIGHTING RULES
Use a dark environment.
Use a strong key light only when needed.
Use rim lights to separate black objects from the background.
Use emissive practical lights inside machines.
Use local lights near active data paths.
Do not wash the entire scene in blue.
Allow large regions of near-black negative space.

# TYPOGRAPHY RULES
Typography must be large and confident.
Use a modern grotesk or geometric sans-serif.
Headlines should feel architectural.
Use small uppercase technical labels for system metadata.
Avoid paragraphs floating inside 3D space.
Keep detailed text in readable DOM overlays.
3D text should be used sparingly.

# TRANSITION RULES
Every scene must have an identifiable transition mechanism.
Possible mechanisms include shutter, data tunnel, folding panel, disintegration, scanline wipe, mechanical rotation, glass fracture and liquid displacement.
Do not use the same transition for every scene.
Transitions should be driven by scene progress.
Transitions must preserve visual continuity.

# RESPONSIVE RULES
Desktop receives the full cinematic experience.
Tablet reduces particle count and depth complexity.
Mobile keeps the storytelling but simplifies expensive effects.
On mobile, cursor interactions become touch interactions.
Do not render thousands of expensive individual objects on low-power devices.
Preserve the scene hierarchy even when reducing detail.

# ACCESSIBILITY
Provide readable HTML equivalents for important text.
Do not place essential information only inside WebGL.
Interactive project links must remain keyboard accessible.
Respect prefers-reduced-motion.
When reduced motion is enabled, keep scene changes but remove aggressive camera and particle motion.

# PERFORMANCE
Use React.memo for static 3D components where useful.
Avoid recreating geometries and materials every render.
Use useMemo for expensive geometry.
Use useRef for animation targets.
Use GSAP contexts and clean them up.
Kill ScrollTriggers on component unmount.
Dispose geometries, materials and textures when appropriate.
Lazy load heavy project media.
Use compressed textures.
Prefer video textures only where they materially improve a project showcase.
Use requestAnimationFrame only where it cannot be replaced by the render loop.

PRIMARY 3D OBJECT: A large suspended cybernetic core made from a transparent glass-metal torus, six rotating mechanical rings, inner luminous circuitry, and a small floating identity glyph. This is the main hero object.

CURSOR / HOVER BEHAVIOR: The object must react continuously to the pointer. Pointer proximity bends nearby particles, rotates the nearest ring toward the pointer, changes emissive intensity, and causes tiny mechanical components to unlock and relock.

SCROLL BEHAVIOR: At the first scroll movement the core rotates 25 degrees on Y, then 18 degrees on X. With continued scrolling it moves toward the camera, grows from 1.0 to 1.45 scale, and passes partially through the camera plane before dissolving into the next scene.

ANIMATION / MOTION: Use layered cinematic motion with non-linear easing. The main object should never remain completely static.

SCENE TRANSITION: Use a digital shutter made from thin horizontal scanlines. The center core becomes overexposed for a fraction of a second, then the screen displaces sideways with a noise shader.

# MASTER SCROLL TIMELINE

- Create one master GSAP timeline for the portfolio.
- Each scene receives a fixed scroll interval rather than competing for the same ScrollTrigger.
- Scene progress must be deterministic from scroll position.
- When scene progress is 0 the scene is in its entrance state.
- When scene progress is 0.5 the scene is fully readable and interactive.
- When scene progress is 1 the scene is prepared for transition.
- Do not let independent animation loops fight GSAP-controlled transforms.
- Idle animation may run only on properties that are not currently owned by the scroll timeline.
- During active scrolling, blend idle rotation into scroll rotation rather than abruptly replacing it.
- When scrolling stops, return gradually to idle motion.

# FRAMER MOTION DOM LAYER

- Use Framer Motion for large headings, labels, buttons and project metadata.
- DOM text must move independently in depth illusion using translateY, scale and opacity.
- Do not attempt to render all typography inside WebGL.
- Use AnimatePresence only for UI elements that genuinely enter and leave.
- Use viewport-safe typography sizes.
- Keep the primary heading visible long enough for the visitor to understand the section.
- Use staggered children only for grouped technical labels.
- Avoid exaggerated bounce animations.

# GLSL TRANSITIONS

- Create a reusable fullscreen transition shader.
- The shader must support progress from 0 to 1.
- Include procedural noise.
- Include directional displacement.
- Include scanline modulation.
- Include subtle RGB channel offset.
- Expose intensity as a uniform.
- Do not make the effect permanently active.
- Use the shader only during scene boundaries.
- Keep the final image readable before the transition reaches full intensity.

# CYBERPUNK ENVIRONMENT

- Use architectural geometry rather than outer-space geometry.
- Add distant buildings, conduits, cables, vents, panels and illuminated signage as background silhouettes.
- Keep background details low-poly or instanced to protect performance.
- Use fog sparingly to create depth.
- Use wet reflective surfaces where appropriate.
- Use subtle scanlines and grain over the final composition.
- Use small animated warning indicators as environmental details.
- Do not create a dystopian city that distracts from the portfolio content.
- The environment is supporting art direction, not the main subject.

# FINAL QUALITY BAR

- The website should feel like one continuous interactive film.
- A visitor should understand that the central subject is an engineer and his systems work.
- The technical content must remain legible and truthful.
- Every major animation must communicate hierarchy, architecture, workflow or interaction.
- Avoid template-like portfolio layouts.
- Avoid generic neon cyberpunk clichés when they do not support the engineering story.
- Prefer physical metaphors: rails, bridges, vaults, machines, terminals, access towers, control rooms and data cores.
- Every scene must have a clear beginning, middle and end.
- Every scene must visually hand off its main object or data signal to the next scene.
- The final build should prioritize polish and consistency over adding unnecessary effects.
